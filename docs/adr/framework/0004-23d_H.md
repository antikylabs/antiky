# 0004: Support 2D, 3D, and 2.3D as first-class modes

## Status

Accepted

## Context

Antiky's primary games use 2D characters and objects in 3D worlds. That style depends on real 2D and
3D capabilities rather than a single voxel or sprite-specific representation.

## Decision

We will make 2D, 3D, and 2.3D game development first-class framework concerns. Antiky uses **2.3D**
to mean 2D characters and objects in a 3D world.

Shared world, command, asset, physics, and rendering contracts will support all three modes. A mode
may use specialized pipelines where its constraints differ.

## Consequences

- The framework cannot assume that every object is a mesh, sprite, voxel, or rigid body.
- Depth, picking, lighting, physics, animation, and batching must work across mixed representations.
- Demos in each mode will provide evidence for shared abstractions and mode-specific extensions.
- Emberwyrd remains the primary design pressure, without making Antiky game-specific.
