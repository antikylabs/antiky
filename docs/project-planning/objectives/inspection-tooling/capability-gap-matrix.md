# Inspection-tooling capability gap matrix

Research snapshot: 2026-08-09

This matrix relates current repository evidence to the capabilities agents need across the game
creation lifecycle. “Accepted direction” means the architecture describes the boundary; it does
not mean the capability is implemented.

## Priority definitions

- **P0 - unlocks trustworthy iteration:** required before skills can safely perform and prove
  general gameplay/world/render work.
- **P1 - unlocks representative game slices:** required for a content-rich, polished vertical
  slice rather than a narrow technology demo.
- **P2 - unlocks production scale or shipping:** required as Antiky games add large worlds,
  persistence, online play, target platforms, and releases.

Priority is not an instruction to build the entire row at once. Each row should enter the framework
through the smallest complete game feature that proves its contract.

## Current foundation

| Capability | Current evidence | Important limit |
| --- | --- | --- |
| Stable identity | UUIDv7 `WorldId`, `EntityId`, `CommandId`, and `SessionId`; development, runtime, action, capture, and call IDs at host boundaries | No implemented stable asset, component-schema, sandbox, change-set, scenario, selection, evidence-bundle, or feedback identity |
| Session determinism | Fixed 60 Hz step, explicit immutable captured input, stable system order, bounded catch-up, pause reasons, single-step, state digest | No input recorder/injector, batch scenario runner, checkpoint restore, seed contract, or cross-run divergence report |
| Single writer and revisions | Session rejects reentrant work; command, control, and world revisions; stale expected-step rejection | No public lease, queued command-batch identity, transaction/change-set revision, or multi-world conflict model |
| Semantic world inspection | Bounded immutable entities, components, `ChildOf`, and named authoring/runtime/render stores with counts and `incomplete` status | One whole published view; no filter, paging cursor, projection selection, schema descriptions, reverse links, spatial query, or revision diff |
| Accepted history | Bounded source-ordered events with commands, revisions, entity IDs, occurrence time, retention policy, and explicit incompleteness | No generic command/event registry, causal trace through systems/projections, history paging, timeline correlation with steps, or persistence backend |
| Development lifecycle | Project/build/process/connection/cleanup state; accepted build revision; changed path/kind; runtime replacement identity | No dependency-aware build graph, compiled artifact identity, build-log query, asset import result, package identity, or target-device run |
| Diagnostics | Stable bounded CLI and Framework codes with severity, source, messages, related IDs, and safe MCP failures | Sparse sources; no per-system spans, source locations, suggested recovery schema, trace tree, warning suppression, or historical query |
| Render measurements | Frame count/FPS, canvas size, draw calls, instances, upload bytes | No frame-time distribution, CPU/GPU phases, render graph, passes, pipelines, resources, memory, overdraw, shader variants, or entity-to-pixel causality |
| Visual capture | Exact connected game-canvas PNG with hash, byte length, runtime/build/session correlation | One unparameterized frame; returned absolute path can disclose local identity; no opaque artifact reference, camera/selection/debug target, sequence/video, frame/time control, color metadata, comparison, or delivery-compression check |
| Semantic mutation | One point-light power command and correction with trusted context, expected revision, stable results, accepted facts, and projection readback | Not a generic component/property/relationship command surface; MCP does not expose caller-scoped capabilities or a preview/change-set flow |
| MCP audit | Bounded source-ordered call log with duration, outcome, correlation IDs, secret-field redaction, and truncation | The MCP client cannot query its own audit through the MCP tool list; no handoff/change-set identity, policy decision, approval, or artifact provenance correlation |

## Cross-lifecycle gaps

| Area | Current or accepted evidence | Gap an agent cannot reliably bridge with a skill | Recommended deep service boundary | Priority |
| --- | --- | --- | --- | --- |
| Project and capability context | CLI reports project, manifest revision, viewport, processes, connection, and build | Agent cannot discover supported component types, commands, queries, subsystem features, authority, limits, or compatibility as one versioned contract | `DevelopmentCapabilities` combining project/tool/schema versions, feature groups, limits, authority classes, and unavailable reasons | P0 |
| Runtime schema registry | Point-light types have explicit versions and validation; architecture requires runtime component metadata | No implemented registry for component fields, units, defaults, ranges, visibility, editability, persistence, migrations, or command mappings | Framework-owned `SchemaRegistry` used by runtime validation, Studio inspectors, MCP descriptions, docs, saves, and migrations | P0 |
| World queries | Whole-world bounded snapshot and hierarchy exist | Large worlds will truncate; agents cannot request one entity, component set, relationship traversal, zone, asset use, spatial region, or named store subset | One typed `WorldQueryService` with filters, field selection, ordering, cursors, counts, revision, and explicit partial results | P0 |
| Revision diffs and subscriptions | Inspection store publishes ordered whole snapshots; runtime publications have sequence checks | MCP clients must poll and compare large snapshots; no semantic “what changed and why” view | `InspectionDelta` stream plus `diffWorld(fromRevision,toRevision,scope)` with changed IDs, fields, causality, and rebuild fallback | P0 |
| Generic authoring commands | Engine session orders commands; point-light slice proves validation, expected revision, authority, fact, projection, correction | Every new editable type would otherwise require bespoke MCP plumbing; agents cannot edit generic typed properties or relationships | `CommandRegistry` plus `executeCommandBatch` over named versioned commands; atomic policy, expected revisions, per-command results, and postcondition readback | P0 |
| Preview and change sets | Architecture calls for previews, commands, correction, and sandbox promotion | No implemented preview, staged delta, atomic commit, change manifest, undo/redo grouping, or diff-before-apply | `ChangeSetService`: preview, validate, compare, commit, correct/revert, journal, ownership, affected targets, evidence links | P0 |
| Sandbox worlds | Accepted architecture places multiple worlds and agent sandboxes under a session | Current `EngineSession` exposes one `worldId`; no clone/create/compare/discard/promote path | `SandboxService` with source revision, scoped copy, resource policy, deterministic compare, promotion as ordinary commands, and disposal | P0 |
| Input capture and injection | Session captures one host-supplied immutable input per advance/step | Agent cannot record semantic actions, inject a trace, control devices/focus, or prove input-to-state latency | Versioned `InputSchema` and `InputTraceService` with semantic actions, device/source, focus owner, timestamps/steps, validation, and safe injection | P0 |
| Scenario replay | Retry-safe one-tick stepping and last-step digest exist | No setup/seed/trace/assertion runner, limited-step/time run, checkpoint, repeatability report, or evidence manifest | Headless-first `ScenarioRunner` producing trace, checkpoints, state/event assertions, diagnostics, timings, captures, and divergence report | P0 |
| Checkpoints and timeline | Event direction includes snapshots/checkpoints; current status keeps only last completed step | Cannot inspect historical state at a step, bisect divergence, restore a sandbox, or correlate input-command-system-event-render phases | Bounded `TimelineService` and sandbox-only checkpoint/restore with explicit durable vs temporary state and hashes | P1 |
| Selection and picking | Stable hierarchy exists; Studio direction requires shared hierarchy/canvas/MCP selection | No implemented selection record, canvas hit, target context, material/pass mapping, or selection-scoped capture | Session `SelectionService` with stable `TargetRef`, hit evidence, current revision, hierarchy, related data, and permission-filtered context | P0 |
| Contextual feedback | Accepted Studio design specifies target-linked comments, queue, changes, and validation evidence | No implemented feedback identity, storage, queue, target context, assignment, evidence link, or resolution commands | Separate versioned `FeedbackService` using `TargetRef`, revisions, untrusted text, bounded attachments, and change/evidence links | P1 |
| Asset registry | Architecture assigns assets to the session; CLI watches a small extension list and has catalog install support | No stable `AssetId`, revision/content identity, type metadata, dependency/dependent graph, usage query, source/provenance, or readiness state | Framework `AssetRegistry` with immutable revisions, typed metadata, content hashes, dependencies, owners, import/build status, and runtime bindings | P0 |
| Import and reimport | Build tracker classifies changed asset paths and waits for a replacement runtime | Cannot inspect importer, settings, warnings, source scale/color/tangent/rig/audio metadata, generated outputs, or reimport delta | `AssetPipelineService` with staged source manifest, deterministic importer profile, validation, generated-artifact hashes, diff, approval, and rollback | P1 |
| Provenance and rights | Skill research requires source/license/hash/transformation manifests | No shared schema or release gate connects an asset to its rights and transformations | `AssetProvenance` schema consumed by asset registry, Studio, evidence bundles, and release gates; block unknown release use | P1 |
| Render-item causality | Point-light inspection maps one authoring entity to runtime and render binding | No generic mapping from entity/component/asset to render item, batch slot, material, pipeline, pass, resource, draw, or pixel selection | Framework-owned `RenderInspectionService` over stable semantic refs and temporary aliases, with rebuild/readback consistency checks | P0 |
| Shader and material inspection | BroMetal compiles typed shaders; CLI only reports generic diagnostics and render counts | Agent cannot inspect reflection, variants, generated code, compile diagnostics by source, material parameters, bindings, fallback, or hot-reload identity | Render-driver `ShaderMaterialInspection` with source/generated hashes, entry points, reflection, variants, diagnostics, bindings, and current GPU generation | P0 |
| Render graph and GPU profile | Architecture assigns passes/resources to render world/driver | No pass graph, resource lifetime, timestamps, memory, overdraw, occlusion, pipeline churn, upload source, or capture marker data | Bounded render-graph/resource inspection and explicit profile runs with CPU/GPU timings, markers, budgets, and target environment | P1 |
| Visual evidence | Canvas PNG is exact and correlated | Cannot capture controlled time, camera, target, debug views, motion, audio, multi-resolution states, or perceptual differences | `VisualEvidenceService` with fixed scenario/time/camera, canvas/selection/debug targets, frame sequences, encoding/color metadata, hashes, and comparison results | P0 |
| System execution and causality | Status lists system order and terminal fault source/system ID | No per-system timing, read/write sets, state delta, signal flow, command/event causality, or runtime toggle/debug view | Opt-in `SystemTraceService` with step spans, system IDs, timings, changed semantic refs, emitted facts/signals, and bounded payloads | P1 |
| Physics | ADR selects authority/execution direction; demos have custom movement/collision work | No shared body/collider/contact/query inspection, deterministic query trace, debug geometry, budget, or safe authoring commands | Physics subsystem inspection earned through a real traversal/combat slice; stable owner IDs, shapes, contacts, queries, authority, timings, and debug capture | P1 |
| Navigation and AI | Accepted runtime model names navigation and AI | No navigation graph/path/query, perception, goal/decision/state, behavior trace, crowd budget, or reproducible AI scenario | Separate typed navigation and AI inspection services with semantic owners, inputs, decisions, paths, failure reasons, and scenario evidence | P1 |
| Ability/combat systems | Ability-system ADR and Combat Arena direction exist | No reusable ability definitions, activation/cost/cooldown/effect/tag trace, hit/damage causality, tuning query, or command surface | Add inspection with the first Framework-owned ability/combat slice; preserve semantic definition, runtime instance, event causality, timing, and balance evidence | P1 |
| Animation | Demos render motion; no Framework animation contract is exposed | Cannot inspect graph/state/clip/time/transition/root motion/notifies/retarget/import or correlate animation to input/gameplay | Animation inspection and controlled playback tied to entity/asset IDs, state transitions, contacts/notifies, performance, and footage | P1 |
| Audio | No audio measurements or semantic events in current inspection | Cannot inspect event routing, buses, voices, attenuation, concurrency, streaming, latency, loudness, clipping, or capture synchronized evidence | Audio inspection service plus scenario-synchronized audio evidence; source rights and platform/device measurements | P1 |
| Game UI and accessibility | No UI tree or accessibility state in Framework inspection | Cannot inspect focus, input ownership, state visibility, layout/safe area, localization expansion, contrast, text scale, motion settings, or announcements | Player-UI semantic inspection with focus/input graph, state bindings, accessibility metadata, screenshots, and automated plus human gates | P1 |
| Save/load and durable state | Event/snapshot architecture is accepted; current history is in-memory and bounded | Cannot persist, migrate, load, compare, validate, or recover game state | Persistence service with versioned snapshots/events, migration reports, corruption handling, deterministic load checks, and sandbox fixtures | P2 |
| Networking and multiplayer | Server-authoritative direction is accepted; current development runtime is local | No connections, players, ownership, replication state, prediction/reconciliation, latency/loss simulation, server trace, or multi-client scenario | Network/session inspection and deterministic multi-process scenario harness, introduced with the first real online feature | P2 |
| Zones and streaming | Architecture defines zones/regions and multiple sessions as open direction | No zone identity, residency, streaming request/reason, handoff, visibility, budget, or world-partition inspection | Zone/streaming service with stable ownership, residency graph, sources, budgets, transitions, and large-world scenario evidence | P2 |
| QA scenarios and assertions | Package tests cover foundational contracts; no live general scenario tool | Skills must orchestrate ad hoc shell/test/capture work and cannot return one comparable run record | Shared `ScenarioRun`/`EvidenceBundle` schemas used by tests, CLI, MCP, Studio, CI, and reviewers | P0 |
| Performance budgets | Current FPS and simple counts are instantaneous | No percentiles, frame pacing, CPU/GPU/system attribution, memory/loading/network/audio budgets, warm-up, environment, or regression comparison | `PerformanceRun` with declared workload/environment, warm-up, samples, percentiles, subsystem metrics, thresholds, comparison, and raw artifact refs | P1 |
| Target devices and compatibility | Browser/WebGPU requirement is documented | No device/browser/adapter/driver feature inventory, scalability profile, run matrix, or artifact-to-result link | Target environment descriptor and remote/local run coordinator that preserves exact build, settings, hardware, browser, adapter, driver, and result | P2 |
| Localization and LQA | Product/skill direction only | No stable strings/context, asset localization, pseudo-localization, missing/stale/placeholder checks, UI overflow evidence, or review package | Localization registry and scenario-driven LQA evidence linked to UI targets and exact build | P2 |
| Build artifacts and release | CLI supervises dev processes and watches readiness; website has release gates | No game build/package command surface, artifact manifest/hash/SBOM/symbols, smoke result, provenance, signing boundary, or published-build mapping | Build/release service with immutable `BuildArtifactId`, target/profile, inputs, outputs, hashes, logs, symbols, tests, approval, rollback, and publication record | P2 |
| Caller authority | Point-light host supplies a trusted local principal and permission; MCP annotations classify tools | No authenticated agent identity, task capability grant, target/path scope, expiry, approval record, or discoverable denial reason | Framework policy decision point plus CLI session capability token/grant; MCP adapts it but never invents authority | P0 |
| Mutation lease and conflicts | Session is internally single-writer and action broker permits one pending browser action | No explicit owner/expiry/scope lease, heartbeat, queued packet, asset lock, or conflict report for human/Studio/agent coordination | Development `MutationLease` and `ChangePacket` protocol over semantic targets/paths with expiry, cancellation, stale checks, and human visibility | P0 |
| Audit and change evidence | CLI call log correlates actions/commands/targets and redacts likely secret fields | No unified chain from brief/handoff through calls, commands, state/render diffs, captures, review, and release | Append-only `ChangeJournal` and immutable evidence manifest linking all identities/hashes without storing untrusted secrets | P0 |
| Security and privacy policy | Loopback services, bounded schemas, origin/runtime checks, safe errors, secret-name redaction, canvas-only capture, and a tested non-identifying Studio terminal profile | Absolute capture paths and arbitrary strings/pixels can still contain PII; no capability-policy inspection, path/network/process/download/upload gates, content-aware scan, retention controls, or evidence export review | Default-deny policy service at host trust boundaries; opaque artifact IDs, permission-filtered metadata, structured decisions, terminal-isolation regression gates, redaction/retention report, and adversarial eval fixtures | P0 |

## Highest-leverage cut points

The matrix is intentionally broad; the first implementation should not be. The deepest reusable
cut points are:

1. **Schema registry + world query + target reference.** These let every client understand and find
   semantic game data without copying internal engine objects.
2. **Command registry + change set + sandbox.** These turn safe inspection into safe general
   authoring while preserving authority, revisions, correction, and one writer.
3. **Input trace + scenario runner + evidence bundle.** These make behavior reproducible and let
   skills prove rather than narrate success.
4. **Render/asset causality + controlled visual evidence.** These connect authored intent to the
   pixels and motion a player experiences.
5. **Capability grants + mutation lease + journal.** These allow humans, Studio, agents, and tests
   to share one development authority without sharing unrestricted access.

Specialized gameplay, rendering, content, performance, and release services should grow through
real features on top of those cut points.

The current seed skills are intentionally excluded from this matrix as architectural evidence.
They are scaffolding to replace when these Antiky-native contracts and evaluation fixtures exist.
