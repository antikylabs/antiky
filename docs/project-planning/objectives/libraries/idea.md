I want to explore two ideas.
 
1. Improving our asset library.
2. Creating shader library.
 
 
---
 
Asset library. Improvements.

Thinking of using a fast model to categorize and tag our assets. Something like codex spark or cereberas 120b or luna low thinking. 

Problem today. WE have a list of assets, and names. But no details about the asset "description" and no details on what assets are available in the packs etc... So if an asset library has 200 assets in it, we don't know what those are...

We need a beter semantic understanding of what assets are available and how to use them etc.


---

Shader library.

One thing that other libraries have are massive amounts of games and stuff built on them, so theres lots of training data and references to look at. So for example there are ton of threejs games out there, especially recently. So they can be learned and repeated well...

The idea here is to build up a library with strong semantic context of shaders that can be reached for.

The question I have... These would be brometal shaders... how does that fit within the antiky framework? What do we expose for that? How would agents use them, how would they learn from them?
